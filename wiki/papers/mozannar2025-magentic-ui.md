## 一句話
Microsoft 做了一個開源的網頁 agent 介面 Magentic-UI，用 6 種機制把人放進 agent 的工作流程，包括一起規劃、一起執行、危險動作先批准等，並實際測試人的參與能讓 agent 表現好多少、使用者覺得哪裡好用、哪裡煩。

## 研究問題
現在的 agent 能自己操作瀏覽器、寫程式、做研究，但在大多數領域仍然比不上人，而且會被惡意網頁操弄，也可能做出不可逆、違反偏好或洩漏個資的動作（p.2）。作者主張解方是**讓 agent 和人有效互動**：結合人的監督和 AI 的效率，從不完美的系統中取得生產力（p.2）。問題是：怎麼用最低的人力成本，把人放進迴路中？

## 方法
- **系統**：以多 agent 架構（Orchestrator 指揮 WebSurfer、Coder、FileSurfer 等）打造的開源介面，**把使用者也當成團隊中的一個 agent**（p.2）。
- **四種評估**（p.3、§7）：
  1. 自主模式下的 benchmark 表現：GAIA、AssistantBench、WebVoyager、WebGames（p.16）
  2. 模擬使用者評估：用 LLM 扮演使用者，把 GAIA 改成互動式 benchmark（p.17–19）
  3. 質性使用者研究：12 位使用者，每人 1 小時，同時進行三個任務（p.19–22）
  4. 安全測試：24 個對抗情境（p.23–24）

## 主要發現
**6 種人在迴路中的機制**（p.3、§3–5）：
- **共同規劃（co-planning）**：執行前，agent 先問釐清問題，再列出可以直接編輯的步驟計畫，使用者按「Accept」才開始（p.5–6）。
- **共同執行（co-tasking）**：使用者可以隨時暫停、接手瀏覽器；agent 也可以在卡住時請使用者幫忙，例如處理 CAPTCHA（p.6–7）。設計原則是「盡量少打擾使用者，只在必要時才打擾」（p.7）。
- **動作守門（action guards）**：每個動作都先標記「一定不可逆／可能不可逆／絕不會不可逆」。一定不可逆的動作請人批准；可能不可逆的動作交給 LLM 判斷要不要問人（p.14）。
- **答案驗證**：使用者可以回頭看每一步的動作，或追問（p.7–8）。
- **記憶**：把成功的計畫存起來，之後重複使用（p.8）。
- **多工**：同時跑多個任務，用狀態指示提示哪個任務需要人回應（p.8）。

**評估結果**
- 自主模式在 GAIA **測試集**的正確率是 42.52%，人類是 92%（p.16）。
- 模擬使用者實驗：給 agent 一個掌握任務額外資訊的模擬使用者，在 GAIA **驗證集**（162 題）上，正確率從 30.3% 提升到 51.9%，**相對提升 71%**，而 agent 只在 10% 的任務中求助（p.18–19）。注意：這和上一點的 42.52% 是不同的題目集，數字不能直接比較。
- 使用者研究的 SUS 可用性分數是 74.58，但只有 41.7% 的人同意「會想常常用」（p.20）。
- 使用者重視共同規劃，因為計畫常涉及主觀偏好，事先很難預料；他們常在執行前修改計畫（p.21）。
- 痛點：延遲最常被提到；推理文字和計畫太冗長（p.21）；長時間的任務紀錄看了會被淹沒（p.25）；**有些人覺得動作守門的確認請求太多**（p.25）。
- 光看最終答案常常無法判斷是否正確，使用者需要回頭看 agent 怎麼做的（p.25–26）。
- 安全測試：預設設定下，24 個對抗情境**全部沒有成功**；但如果關掉防護，prompt 注入攻擊就能讓 agent 外洩 SSH 私鑰等資料（p.23–24）。

## 設計啟示
- 把介面互動的成本「前移」到規劃階段：執行前對齊計畫，比事後修正便宜得多（p.5）。
- 計畫要讓人看得懂也改得動：用自然語言列出步驟，容易驗證，但會犧牲彈性（p.5、p.25）。
- 確認的次數需要依照使用者對風險的容忍度和信任程度調整（p.25）。
- 讓 agent 在背景跑時，需要更好的「它做了什麼」摘要，例如影片摘要（p.25–26）。
- 安全不能只靠模型判斷，還要搭配沙盒、獨立瀏覽器、允許網站清單等多層防護（p.23–24、p.26）。

## 限制
- 沒有測量真實的生產力提升，只做了模擬評估和質性研究（p.26）。
- 使用者研究只有 12 人、每人 1 小時，參與者都熟悉 agent，也沒有測試記憶功能（p.19）。
- 模擬使用者是 LLM，不是真人（p.17–18）。
- 只用英文設計和測試（p.26）。

## 與其他論文的關係
- 作者明確表示，這個系統是用來實作 [[papers/bansal2024-human-agent-communication]] 提出的溝通挑戰：共同規劃對應 U1、進度條和紀錄對應 A2／A3、答案驗證對應 A5（p.4、p.25）。
- 依 [[papers/feng2025-levels-of-autonomy]] 的框架來看，Magentic-UI 的預設模式接近 L2「協作者」：可以直接編輯計畫、隨時接手（綜合：[[papers/feng2025-levels-of-autonomy]] p.5–6、本篇 p.5–7）。Feng 也把 OpenAI Operator 歸為 L2（[[papers/feng2025-levels-of-autonomy]] p.4 註 3）。
- 為 [[debates/how-much-human-oversight]] 提供了實證：人的參與能大幅提升正確率，但確認太多會讓人厭煩。
- 共同規劃也是縮小 [[concepts/gulf-of-envisioning]] 的一種方式：agent 先提出計畫，使用者只需要修改，不用從零想清楚（綜合：[[papers/subramonyam2024-gulf-of-envisioning]] p.8、本篇 p.21）。
