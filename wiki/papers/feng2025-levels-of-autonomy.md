## 一句話
agent 要多自主，不是「能力越強就越自主」的必然結果，而是設計者可以刻意做的決定。作者依照「使用者扮演什麼角色」把自主性分成五級：操作者、協作者、顧問、批准者、觀察者。

## 研究問題
自主性是一把雙面刃：能帶來突破性的應用，也會放大風險，例如詐騙、個資外洩、人類技能退化（p.2）。可是業界的研究和評測大多只看「能不能自主完成任務」（p.2）。這篇要問：agent 開發者要怎麼校準 agent 該有的自主程度？

## 方法
**立場論文（essay）**。作者提出概念框架，並用同一個例子貫穿五個等級來說明：同一個會操作電腦的 agent、同樣的工具、同一個使用者請求（「幫我了解 ChatGPT 推出後生成式 AI 對美國經濟的影響」）（p.4）。作者說明這些情境只是**描述**，不是建議的最佳實作（p.4）。

## 主要發現
- **自主性和能力分開**：自主性是「agent 被設計成在多大程度上不需要使用者參與」；能力強的 agent 也可以被設計成每一步都先問人（p.2、p.3）。
- **agency 和 autonomy 也分開**：agency 是「能有意圖地行動的能力」，主要由可用的工具決定；autonomy 是「不需使用者參與的程度」。只能用計算機的 agent 可以 agency 低、autonomy 高（p.3）。
- **五個等級**（Figure 1，p.1；§3，p.4–8）：
  - **L1 操作者**：使用者主導規劃和決策，agent 在被叫時才幫忙，類似 Copilot 的比喻；適合高風險、高專業的工作（p.4–5）。
  - **L2 協作者**：雙方一起規劃、分工、執行，使用者可以直接修改計畫、隨時接手；溝通最頻繁（p.5–6）。
  - **L3 顧問**：agent 主導規劃和執行，在需要專業知識或偏好時諮詢使用者；使用者不能直接接手，只能透過訊息提出修改（p.6–7）。
  - **L4 批准者**：agent 只在遇到無法自己解決的障礙（例如需要密碼、重大動作）時才找使用者；適合大量低風險決策的任務（p.7）。
  - **L5 觀察者**：完全自主，使用者只能看活動紀錄，唯一的控制是緊急停止開關（p.8）。
- 自主性越高，越要注意 L4 的「**橡皮圖章**」問題：使用者失去參與感時，會不經思考就批准，甚至可能被不對齊的 agent 一步步說服而批准危險動作（p.8）。
- **越自主不代表越好**：提高自主性需要在效用、效率、責任歸屬和成本之間取捨（p.9）。
- 應用一：**自主性證書（autonomy certificates）**，由第三方機構核發，標明 agent 最高能運作在哪一級（§4，p.9–10）。
- 應用二：**協助式評估（assisted evaluation）**，讓一位待命的使用者在 agent 需要時協助，逐步增加參與程度，找出 agent 達標所需的「最少使用者參與」，以此判定等級（§5，p.11–12）。

## 設計啟示
- 先決定 agent 該在哪一級運作，再依照那一級設計控制機制，例如 L2 要能隨時接手、L4 要讓使用者事先指定哪些動作需要批准、L5 要有監看工具和緊急停止開關（p.5–8）。
- 如果想保留使用者的技能和批判思考，可以刻意選低一點的等級（L1、L2），讓人親自做部分工作（p.5–6）。
- 每一級都有尚未解決的設計問題，例如 L3 什麼時候該諮詢使用者、L4 怎麼避免使用者無意識地蓋章（p.5–8）。

## 限制
- 概念框架，**沒有使用者研究或實驗**驗證（p.4）。
- 例子刻意保持描述性，不保證是最佳實作（p.4）。
- 自主性證書和協助式評估都只是初步構想（p.9–12）；協助式評估每多一級就要多跑一輪，成本高（p.11–12）。

## 與其他論文的關係
- 把 [[papers/bansal2024-human-agent-communication]] 的「人該介入多少」（X3）變成一個可以明確選擇的設計維度（綜合：[[papers/bansal2024-human-agent-communication]] p.8、本篇 p.2）。
- L4 的「只在高代價或預先指定的情況才找使用者」，和 Bansal 的 A2「高代價動作前取得許可」相同（綜合：[[papers/bansal2024-human-agent-communication]] p.15、本篇 p.7）。
- 和 Bansal 的強調重點不同：Bansal 認為使用者驗證 agent 行為是必要的（X1）；Feng 則認為某些情況下使用者介入反而會**降低**品質，所以 L5 有時是合理的。見 [[debates/how-much-human-oversight]]。
