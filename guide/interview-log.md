## 需求摘要（使用者回覆「確認」）

1. **主題與目的**：整理 AI-Native 介面與 Agentic UX 的論文，作為教學 HTML 簡報的知識來源。
2. **讀者**：新手、略懂的人、專業人士都有。最低目標是讀完能說出設計趨勢是什麼、為什麼會出現。
3. **寫法**：寫給中間程度的讀者，術語第一次出現時附一句話解釋或連到 concept 頁。
4. **頁面類型**：papers／concepts／trends／debates，加上 index.md 和 log.md；檔名用英文 slug。
5. **語言**：繁體中文，通用英文術語直接用英文；只維護中文版，需要英文時即時翻譯。
6. **出處**：論點層級加章節或頁碼；數字和引述一定要附頁碼；跨論文推論標「（綜合：…）」。
7. **矛盾**：開 debates/ 頁，並列雙方主張，加上有出處的情境分析，不判斷誰對。
8. **Ingest**：一次一篇；先給計畫，然後依序寫 paper 頁、更新 concept/trend/debate 頁、更新 index、記 log、跑 lint，最後停下讓使用者 commit。
9. **不能做**：改 raw/、用外部知識補內容、刪改 log 的舊紀錄、自己 commit 或 push。
10. **產出**：教學 HTML 簡報，以 trends/ 為骨架，每張投影片標出對應的 wiki 頁。
11. **Lint**：只列警告、不擋 commit，共 8 項檢查，每次結果都記進 log.md。
12. **環境**：macOS，Python 腳本一律用 python3 執行。

## 與 AGENTS.reference.md 的比較（2026-11-23）

**決定**：以訪談生成的版本為正式 `AGENTS.md`，再從參考版併入 3 點。

| 面向 | 訪談版（正式） | 參考版 | 差異原因 |
|---|---|---|---|
| 讀者 | 程度不一：新手、略懂的人、專業人士 | 修課的大學生 | 訪談時使用者說要給更多人看，讀者範圍因此變大 |
| 寫法 | 中間程度 + 術語附解釋，concept 頁必須有給新手的定義 | 先講結論再講證據的同學筆記 | 為了照顧新手 |
| 頁面類型 | 多了 `trends/` | papers／concepts／debates | 使用者的目標是讓讀者「知道趨勢和原因」；trend 頁也是簡報骨架 |
| 語言 | 通用英文術語直接用英文；英文版由 agent 即時翻譯 | 專有名詞一律附英文 | 使用者想要能切換中英文 |
| 矛盾處理 | 加上「有出處的情境分析」，並規定開頁標準 | 有「情境差異」段落 | 大致相同，訪談版規定得比較細 |
| Ingest | 先給計畫、等確認才動手；lint 只列警告 | lint 全部通過才算完成 | 訪談時使用者選擇只列警告 |
| 產出 | 明確寫出作業評分的「wiki 和簡報要對應」 | 只說照 workflow 做 | 訪談時使用者貼了作業說明 |
| 從參考版併入 | Query 規則、直接引述每次不超過一句、「待查：<要查什麼>」 | — | 訪談沒問到，但值得保留 |
| 新增 | 頁碼一律用 PDF 頁碼；所有 Python 腳本用 python3 | `python` | 環境是 macOS |

**觀察**：訪談版最大的不同，來自參考答案沒有預設的兩個回答：讀者範圍變大，以及要求能切換中英文。訪談沒問到的項目（Query、引述長度），參考版反而比較周全。訪談能把需求問得更深，但只能涵蓋有被問到的題目。
